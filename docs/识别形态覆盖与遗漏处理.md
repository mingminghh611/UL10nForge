# 识别形态覆盖与遗漏处理

> 2026-08 识别模块复盘（0.13.x→0.14.1）后确立的治理文档。
> 核心结论：**跳过是哑信号**——被跳过的文本不产生任何可见信号（不报错、
> 不进池、不出现在审计里），只有用户实测才能感知。多轮「0 失败」审计
> 测的是已知样本不失败，不是未知形态不漏。本文件把「形态覆盖」变成
> **可审计事实**，把「用户实测遗漏」变成**制度化流程**。

## 1. 形态注册表（显式清单）

代码：`hanhua/core/tooling/morphology.py`。每个来源文件归类到注册表形态；
**未知形态 → 显式告警**（扫描报告 warnings + UI Toast），绝不静默按最低
策略处理。元测试 `tests/test_morphology.py::test_registry_coverage_complete`
强制每个形态登记锚点覆盖，新增形态不登记 → 测试失败。

| 形态 | 提取器 | 文本先验 | 实证锚点 |
|---|---|---|---|
| mono_csharp | extract_dll_user_strings | mixed | C# 验证链 fixture |
| **mono_unityscript** | extract_dll_user_strings | **dense** | lilys-day-off 854 条（0.14.0 含空格 / 0.14.1 语气词） |
| **mono_boo** | extract_dll_user_strings | **dense** | fallback 测试（0.14.0） |
| mono_other | extract_dll_user_strings | mixed | StgAssembly_* manifest 测试 |
| asset_unity | extract_asset_file | mixed | typetree/rawstr/TextAsset 系列 + 证据分层（0.14.1） |
| il2cpp_metadata | extract_metadata_strings | mixed | parse_string_literals 系列 |

**文本先验**：dense = 该形态字符串字面量几乎全是显示文本（UnityScript/Boo
语言编译产物）；mixed = 显示文本与键名/结构值混合。先验决定启发式边界
（如 0.14.0 的「无空格不升级」边界违背了 unityscript 的 dense 先验，
误杀 29 条语气词——先验显式化后此类边界在设计时即可被看见）。

## 2. 证据分层（代码结构保证）

提取决策证据强度：**确定性证据**（typetree UI 字段白名单、ui setter 验证
链、Interaction 提示）> **形态性证据**（dense 先验）> **猜测性证据**
（uppercase、句子形态、credit 反模式…）。

- **硬结构规则**（JSON/URL/路径/GUID/纯数字/键名——翻译会破坏功能）：
  任何证据强度下都生效。
- **软猜测规则**（署名/版权反模式 `is_credit_like`、lorem、jam、键盘噪音）：
  只允许在低于它的证据强度上生效。确定性显示字段条目由
  `extractor._should_downgrade_pending` 保证只被硬结构降级。

实证：`'A game by Kyuppin'`（level13 m_Text 显示字段）曾被 credit 软猜测
规则降级跳过——0.14.1 分层后消除。**修改提取规则时先问：这条规则属于
硬结构还是软猜测？它可能推翻哪一层证据？**

## 3. 用户实测遗漏 SOP（制度化流程）

用户实测发现遗漏（游戏中出现未汉化文本）→ 按此流程处理：

1. **定位载体形态**：遗漏文本在哪个文件？（DLL / level / sharedassets /
   txt / 其他）→ 归类到注册表形态，或确认是新形态。
2. **证据分层审查**：该文本为何被跳过？是规则边界（软猜测推翻证据？
   形态先验未显式化？）还是提取器未覆盖？——**不要直接加规则**，先回答
   「它违反了哪一层证据原则」。
3. **真实样本锚点**：把该文本变成 fixture 测试断言「**已知文本必须进池**」
   （断言进池，不是断言不崩溃）。真实样本无法进 git 的（大 DLL），用
   双名 fixture / 最小化构造，并保留真实路径验证记录。
4. **形态登记**：若是新形态，先在 `morphology.py` 注册（含先验与实证），
   再在 `test_morphology.py::_COVERAGE` 登记锚点——元测试强制。
5. **全量回归 + 提交**：本地提交（不 push，除非用户明确要求）。

## 4. 明确跳过的自动化（及未来触发条件）

复盘结论：以下自动化**抓不到历史实证中的小遗漏**（29/881=3%、1/37），
且误报成本高——**现阶段不做**：

| 自动化 | 为什么不做 | 未来触发条件 |
|---|---|---|
| 形态级 skipped 率告警 | 只抓大遗漏（94% 类）；小遗漏（3%）无感；真噪音游戏误报高 | 出现「整形态大遗漏」且未被用户首测发现（即自动化成为唯一检测手段） |
| 提取器变更前后产出对比门禁 | 防大变化；小遗漏变化无感；流程变重 | 同上，或提取器改动频率高到回归风险实测上升 |
| 同形态横向差分检测 | 均匀错误（两游戏都被跳过语气词）显示不出差异 | 锚点矩阵覆盖 ≥10 形态且样本充足后 |
| 运行时截图 vs 提取池比对 | 成本最高 | 用户明确要求终极手段时 |

自动化价值排序（诚实版）：**证据分层（原则）> 形态注册表（清单）>
用户实测制度化（纪律）> 自动化仪表盘（暂不投）**。用户实测是唯一可靠
的小遗漏探测器——每一次实测发现都在喂第 3 节的流程。
